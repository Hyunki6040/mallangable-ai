## 3. 確認された欠陥

| 重大度 | タイトル | 境界 | 観測結果 |

| low | `decide()` の下限アクションの例外が主体・方向を見ていない | エージェント・別レイヤーの主体 → PDP の有効状態の遷移 | 同じ状態 S1 に対し、`activate` は拒否(深さ)、`revert(target=S1)` は許可[記録] |

### 3.1 下限アクションの例外の範囲(`docs/04-control-spectrum.md:153`)

- 下位の信頼主体: 委任を受けたエージェント(プロンプトインジェクション可能)、監視者、別レイヤーのユーザー。
- 再現: 4.8 の疑似コードをそのまま移植しました。ポリシーは深さの上限 D3、権限 `[tasks.read]`、`gated` で、記録された状態 S1 は D4 で `net.slack.post` を持ちます。結果は、`activate(S1)` が `('deny','depth')`、`revert(target=S1)` が主体と無関係に `('allow',['log'])` です。
- 条件: ホストが 4.8 をそのまま実装し、`revert` が任意の StateId を受け取り、やり直しとしても使われる場合(5.5)に成立します。ランタイムブローカーの呼び出しごとの PDP 確認が実際の権限使用を防ぐかどうかは実装によって異なるため、主張しません。
- 影響: この状態遷移はテナントの上限、G5、保留の再検証を飛ばします。I4 と 5.4(E10)に反します。
- 対処(今回の改訂): `floor_scoped(req)` を追加しました。人の所有者、自分のレイヤー、以前の状態、権限・深さの非増加をすべて満たす場合にだけ下限とみなします。それ以外の `revert` は `as_activate` で同じ判定を経ます。`uses_destructive` の分岐も追加し、5.5 と 7.11 に同じルールを記しました。

### 3.2 検査ツールの出力インジェクション(`tools/check_schemas.py:29`、`:26`)

- 下位の信頼主体: `check_schemas.py <schema> FILE` コマンドに渡す外部文書やファイル名の作成者。
- 再現: lexicon-pack の `concepts` キーを `"x\e]0;PWNED\a\e[2K\rOK   forged.yaml[0]\n::error title=forged::…"` にしました。このキーが `json_path` にそのまま入り、出力されました。
- 影響: 出力とログだけが偽造されます(ウィンドウタイトル、偽の `OK` 行、GitHub Actions のアノテーション)。判定、終了コード、ファイル、認証情報には影響しません。
- 対処(今回の改訂): 出力するすべての文字列に `safe()`(repr エスケープ、300文字で切り詰め)を使います。回帰検査として assert を1つ入れました。サンドボックスで再実行した結果、ESC 0個、`::` 行 0個です。

## 4. さらなる検証が必要

| タイトル | 位置 | 詰まった点 | 状態 |

## 5. 強化メモ(欠陥ではない、反映の有無)

- 反映: change-record の決定的な契約は、実行可能な形式が1つ以上なければなりません。記述形式しかない記録は今後拒否されます。
- 反映: `permissions_delta` の再計算、`approved_by` は人の主体であり `agent` とは異なる必要がある。スキーマの説明と 7.11 に入れました。
- 反映: `network.allow` とポリシーの `allowlist` が IP リテラルを拒否します。パブリックサフィックスのワイルドカード、egress 権限の存在、`setKnob` default ⊆ ceiling は準拠検査器(conformance validator)の MUST として記し、`False` を期待する回帰ケースを追加しました。
- 反映: YAML エイリアスと 1 MiB 超のファイルを拒否します。555 B のエイリアス爆弾が 75.5 MB を出力していた問題と、601 B の入力による OOM がなくなりました。文書ごとの例外は隔離しました(非文字列キー)。
- 反映: `design_space.py --profile`・`--check` は失敗判定で終了コード1を返し、重複キーと非オブジェクトの JSON を拒否します。
- 反映: CI `permissions: contents: read`。4.7 の抜粋の `net.allowlist` を `net.slack.post` に修正しました(L-04)。
- 未反映(提案): Actions をコミット SHA で固定、`requirements.txt` のハッシュ固定、capability id `*` の意味の定義、共有時の `content_hash` の必須化、承認の指紋フィールド。

肯定的なパターン: `yaml.safe_load` の使用。文書をまたぐルールを `ACCEPTED (validator MUST check)` として明示する回帰構造。深さと形態の対応を3か所で強制。
